# Запуск уведомлений первой фазы

Целевые проекты: Vercel `detail-flow1/detailflow`, Supabase `stxfbarigoutglfqqhwi`.

## 1. База и сайт

Выполнить `supabase/deploy/phase_one_040_044.sql`, затем `verify_phase_one.sql`. Проверка возвращает `true` и три таблицы с включённым RLS. Миграция сама включает RLS и ограничивает доступ; для неё допустим обычный запуск `Run without RLS` без автоматической правки редактора. `DROP` заменяет только политику и триггер, не таблицы и не данные.

После выкладки сайта `/api/health` должен вернуть HTTP 200. Перед настройкой расписания проверить, что production использует новый обработчик очереди.

## 2. Push

Выполнить `node scripts/generate-push-keys.mjs`. Файл `.tooling/push-production.env` содержит три переменные для Vercel **Production**. `VAPID_PRIVATE_KEY` сохранить как Secret. Ни одну из них не называть с префиксом `VITE_`. Перезапустить деплой после добавления переменных. Повторный запуск генератора сохраняет прежнюю пару ключей: её замена потребует новой подписки устройств.

Владелец и мастер включают «Сповіщення» на своих устройствах. На iPhone открыть установленное приложение с главного экрана. Проверить назначение → сдачу на проверку → подтверждение. В тексте push нет контактов клиента или суммы зарплаты. Выход из аккаунта отключает подписку этого браузера.

## 3. Почта

Существующие `SENDPULSE_API_KEY`, `SENDPULSE_API_FROM_EMAIL`, `SENDPULSE_API_FROM_NAME` должны быть настроены в Production. Нужен постоянный API key и подтверждённый отправитель. Временный OAuth-токен истекает через час. Подробности: [авторизация SendPulse](https://sendpulse.com/integrations/api#auth), [SMTP API](https://sendpulse.com/integrations/api/smtp).

Приглашения и восстановление пароля используют **Supabase Auth SMTP**, это отдельная настройка от клиентских напоминаний SendPulse. Проверить SMTP и разрешённые адреса перенаправления `/login`, `/login?role=master&activate=master`, `/login?role=admin&activate=admin` основного сайта.

Для повторных визитов включить согласие в карточке конкретного клиента, переключатель в настройках и интервал услуги. По умолчанию согласие выключено. Провайдер может принять письмо, но не доставить его во входящие: журнал приложения называет этот статус «Прийнято провайдером».

## 4. Ежеминутный запуск

В Supabase включить расширения `pg_cron` и `pg_net`. В Vault создать секрет с именем `detailflow_cron_secret`, значение — **уже существующий CRON_SECRET из Vercel Production**. Не вставлять его в Git, переписку или URL.

После деплоя выполнить `supabase/deploy/configure_notification_cron.sql`. Он создаёт/обновляет только задание `detailflow-notifications`, запускающее HTTPS-обработчик каждую минуту. Схема соответствует [документации Supabase](https://supabase.com/docs/guides/functions/schedule-functions). Не дублировать это расписание в другом сервисе.

Проверить Cron → History, а затем ответы HTTP в журнале pg_net: успех запуска cron означает постановку HTTP-запроса, а не доставку письма. Должен приходить HTTP 200 от `/api/send-reminders`. HTTP 401 — секреты не совпадают; 503 — конфигурация или обработка недоступна. Не публиковать полные записи очереди HTTP: они могут содержать заголовок авторизации.

Сначала проверить тестовую запись с согласованным тестовым адресом, а не контактами клиентов. Проверить письмо во входящих и журнал провайдера, push на двух устройствах, отмену/перенос записи и блокировку мастера. Автоматические повторы выполняются только при явном отказе. При неизвестном результате отправки приложение требует ручной проверки, чтобы не отправлять дубликаты.

## 5. Приёмка и остановка

Убедиться, что назначение попало мастеру, отправка на проверку — владельцу, подтверждение — в заработок. В журнале проверить отсутствие повторных сообщений при повторном запуске обработчика. При необходимости остановить только задание `detailflow-notifications` через переключатель Active в Supabase Cron; данные очереди сохраняются.

Код и локальные тесты не подтверждают фактическую настройку production. Доставка письма, push и работа расписания отмечаются завершёнными только после проверки на реальных тестовых аккаунтах.
