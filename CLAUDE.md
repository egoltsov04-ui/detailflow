# Detailflow: контекст проекта для Claude Code

## Что это

SaaS для детейлинг-студий в Украине: запис, замовлення, майстри, чеки, склад, фінанси, аналітика. Multi-tenant: каждая студия видит только свои данные. Владелец проекта собирает продукт с помощью AI, сам код не пишет, общается по-русски. Интерфейс продукта на украинском (i18n). Любой новый текст добавляй во все существующие языки.

## Стек (по INFRA_AUDIT.md от 2026-11-06)

- Фронтенд: Vite + React, одностраничное приложение (SPA). Это не Next.js.
- Сервер: Vercel Functions в `api/` (booking-requests, staff, public, push, health, WayForPay, send-reminders), общие помощники в `server/lib/`.
- База, авторизация, файлы: Supabase (PostgreSQL, Auth, Storage, бакет `job-photos`). В браузере используются `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`, поэтому граница между студиями это RLS и права RPC, а не фронтенд.
- Письма приложения: SendPulse API. Письма Supabase Auth (приглашения, сброс пароля): отдельный SMTP в настройках Auth.
- Push: Web Push (VAPID). Оплата подписок: WayForPay в коде, по умолчанию режим `manual` (оплата и продление через менеджера в Telegram).
- Бэкапы: `scripts/weekly-encrypted-backup.mjs` и `scripts/restore-backup.mjs` для self-hosted стека, хранилище Backblaze B2 через rclone crypt, инструкция и журнал восстановлений в `docs/BACKUPS.md`. Восстановление с настоящего B2 проверено на сервере 2026-11-08 (staging). Для восстановления нужен ещё ключ Vault `pgsodium_root.key`, см. `docs/BACKUPS.md`.
- Тесты: Playwright в `tests/e2e/`, CI в `.github/workflows/`.
- Хостинг сейчас: Vercel и Supabase Cloud. Цель: собственный сервер (скилл `detailflow-selfhost-infra`).

## Команды

Из `package.json`. Если scripts поменялись, сначала сверь с ним. Нужен Node 24 (как в CI `.github/workflows/verify.yml`): на Node 22 `npm test` падает сразу на флаге `--test-isolation=none`, временная замена `--experimental-test-isolation=none`.

- `npm ci`: установка зависимостей.
- `npm run dev`: локальный запуск фронтенда (Vite).
- `npm run lint`: проверка типов TypeScript для `src/` и `api/` (`tsc --noEmit`). Это не ESLint.
- `npm test`: unit и проверки базы на PGlite (`scripts/*.test.mjs`). Перед ними автоматически собираются сводные миграции и конфиг тарифов.
- `npm run build`: сборка в `dist/`. Перед ней собирается конфиг тарифов и запускается `scripts/check-env-isolation.mjs`: он проверяет, что staging не смотрит в боевую базу, но только при `VERCEL_ENV=preview` или `DEPLOYMENT_ENV=staging`, иначе пропускается.
- `npm run test:e2e`: E2E на Playwright (`tests/e2e/`).

## Роли

Владелец студии, адміністратор (отдельный флаг «Доступ до фінансів та зарплат»), майстер, support (панель `/admin`, только сотрудники платформы). Права проверяются на сервере и в RLS, скрытие пунктов меню не защита.

## Принципы продукта (детали в скилле `detailflow-product-rules`)

- Одна сущность, одно место для действий: заказ открывается в одной общей панели, остальные экраны только показывают.
- Меню из 8 разделов: Огляд, Роботи, Клієнти, Фінанси, Склад, Команда, Аналітика, Налаштування.
- Графики и расчёты Аналітики без прямого запроса не менять. 3D и анимации работ не делаем.
- Тёмная тема, мобильная версия обязательна (375 px без горизонтального скролла).

## Дизайн-система

- Токены (цвета, шрифты, размеры, отступы, скругления, тени, слои, 44 px): `src/styles/tokens.css`. Новые цвета и размеры не пишем числами, только через переменные.
- Базовые компоненты: `src/styles/components.css` (кнопки `primary` / `secondary` / `text-btn` / `danger`, вкладки, фильтры-плашки `ui-chips`, поля, `StatCard`, `Badge`, таблицы, окна, пустые состояния, ошибки) и `src/components/UI.tsx`. Сначала ищи готовый компонент, потом пиши свой.
- Шрифты лежат в `public/fonts` (Manrope, Montserrat для заголовков), к Google Fonts не обращаемся.
- Старые стили (`styles.css`, `ux-polish.css` и файлы экранов) ещё содержат правила светлой темы и разовые цвета, они убираются по мере прохода по экранам (этап 3 редизайна).

## Безопасность (детали в скилле `detailflow-security-review`)

- Любая таблица с данными студии содержит `studio_id` и защищена RLS. Студию берём из сессии, не из параметров запроса.
- `SUPABASE_SERVICE_ROLE_KEY`, `CRON_SECRET`, ключи SendPulse, VAPID private и WayForPay secret только на сервере. В `VITE_*` секретов нет.
- Секреты не печатай в ответах и логах, `.env` не коммить.
